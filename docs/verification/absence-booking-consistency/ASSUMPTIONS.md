# Assumptions and owners

| ID | Premise | Owner and validation |
| --- | --- | --- |
| A1 | P1 compares identical eligible course pools. Course codes identify rows and the model's natural-number codes preserve the byte order of the real strings. | Course catalog and resolver owners. Inspect the unique course code constraint, SQL `COLLATE "C"`, and Go string order. The rank-chain HTTP regression uses eligible tied ranks in different cycles. No proof of pool construction or all rule types is asserted. |
| A2 | P2 receives authentic audience information and successful reads of bookability. The model's admin exclusion covers this gate only. | Authentication and absence backend owners. Inspect route authentication, `studentFacing`, and the shared course visibility view. The mixed UI/public HTTP regression tests a course hidden to students. |
| A3 | Explicit merge override metadata, effective fallback metadata and root priorities refer to one coherent catalog. | Course catalog and PostgreSQL owners. Verify the explicit `course_merge_groups.sit_in_rule_id` is independent of `course_rule_configs.sit_in_rule_id`. The priority test exercises both branches with real rows. |
| A4 | Local civil boundaries are monotone and the date parser and the timezone database agree on the containing day. All times modeled here are session starts, and all dates are finite representable dates. | Institute configuration and backend runtime owners. Compare Go's institute timezone and PostgreSQL tzdata. The Bangkok early-hour integration case is exercised. Other configured zones and representative DST boundaries are follow-up deployment checks. |
| A5 | The TypeScript per-day selection and history identify the intended source row, method, target and target merge group. The model treats exact ordered session-ID encodings as equality after canonical sorting. Production uses UUID IDs. A shared alias is applicable only to an ordinary suggested merged selection. | Form owners. Correspondence tests cover distinct targets, two same-merge peers with distinct selections, shared merged-day choices, recorded priority history, and staff override payloads. The model does not verify list-to-JSON serialization, date extrema, session deduplication or stale history state. |
| A6 | Publication is a single atomic primary PostgreSQL commit. All batch records, snapshots and the idempotency response in scope share that commit. A retained key is the authenticated scope, actor and key. Requests with equal fingerprints are considered equivalent for replay. | API and DB owners. Inspect transaction adapter, the unique idempotency index, request fingerprint construction and replay order. Local HTTP tests exercise write rollback and replay across handler instances with independent pools. Retention expiry, storage failure and uncooperative writers are outside this theorem. |
| A7 | The model's staging predicate represents a successful completed validation of every item against its applicable facts. The model starts tracking new keys from arbitrary catalog facts with an empty journal for those keys. Previously published keys are represented by arbitrary reachable prefixes. | Backend owners. The real resolver can read several SQL statements and batch items in sequence. The model does not assert a single coherent read snapshot across those statements under concurrent policy updates. |
| A8 | Lookup and publication are separate. A policy update can commit after booking validation. | Policy and booking owners. The deterministic PostgreSQL probe reports an HTTP 201 and persisted assignment despite the intervening disable. A stronger guarantee would need a shared lock or policy epoch across all relevant writers and submitters. |
| A9 | Deployment correspondence requires the exact verified code and matching configuration. | Railway and release owners. Deployment metadata reported an older source commit. Live replica count, database isolation overrides, database failover and read routing, session/idle timeouts, configuration, and rollout skew are UNKNOWN. No live write, fault test, or load test was run. |

Lean checks the model under the pinned standard library. The axiom audit allows only `propext`, `Classical.choice`, and `Quot.sound`. The Go compiler, TypeScript runtime, PostgreSQL transaction engine, timezone rules, and adapters are trusted implementation boundaries with empirical checks where listed.
